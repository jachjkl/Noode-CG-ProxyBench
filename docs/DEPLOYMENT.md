# Deployment

The default destination is the independent `jachjkl/Noode-CG-ProxyBench` repository. Overall settings can select another personal repository and branch containing the complete cloud source. Owner-authenticated Windows dispatch requests Ubuntu discovery and publication. The original repository is not a source or result write target.

Double-click the Windows EXE beside the desired runtime location. It creates `Noode-CG-ProxyBench` next to that EXE and preserves existing rules, profiles, results and logs. A private package can contain the explicitly requested local profile; keep it local. Public source and public packages contain no proxy credentials. TCP/TLS mode needs no profile.

Select the method, save ordinary and Japanese counts, and start. Initial discovery fetches both full feeds plus 10,000 official candidates; later rounds exclude every earlier window-session address. Local methods reuse the downloaded session pool. Final competition measures previous cloud entries again before ranking. Automatic publication requires configured quotas; manual push may publish actual qualified counts after retesting.

Public files are fetched through several mirrors. Download mirrors cannot accept authenticated GitHub writes. Ubuntu receives an allowlisted result blob, validates mode, namespace, digest, quotas, ranks and text consistency, then commits only the selected output namespace. The desktop reports completion only after confirmation. Network failures preserve pending archives for retry.

## Moving to another repository or computer

1. Upload the complete cloud source at the new repository root, including `.github/workflows/proxybench.yml` and `proxybench-publish.yml`, and enable Actions. Keep the proxy profile local.
2. In the desktop's Overall settings, enter `owner/repository` (or its official GitHub URL) and the existing branch. Save these fields.
3. Use Login GitHub to open the bundled CLI's official web authorization. Authenticate as the repository owner. On a new computer, perform this step again. No repository password field is needed.
4. Use Check connection. It reads account identity, repository write permissions, branch existence and workflow readiness. If the repository was renamed, save the detected canonical address.
5. Start discovery or manually push saved measured results. Failed checks or uploads retain local qualified IPs and pending archives. Stop and save before changing destinations.

Settings are stored in `data/github-settings.json`, separately from session caches. Both engines use the saved target and branch. Auxiliary cloud reads discard stale results if the target changes during a read. Authentication remains in GitHub CLI's credential mechanism. Public mirrors are attempted before official authenticated reads; private published lists can fall back to already verified official API content. Writes use GitHub APIs followed by owner-only Ubuntu validation. Source upload must preserve workflow files, and the selected branch must contain them. The source package includes placeholder output paths; the first valid publication populates them.
