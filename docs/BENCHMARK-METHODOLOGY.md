# Measurement methodology

## Proxy method

Candidate entry TCP connections are screened concurrently before expensive proxy requests. Both entry and final composite limits are strict. Each admitted candidate becomes an authenticated named outbound in an isolated Mihomo rule-mode core. At least five requests per site measure Google, public Cloudflare trace, and GitHub. Remove exactly one highest and one lowest successful observation from each site, average the retained observations, then average the three site means. Failure counts always include failed observations and cannot be removed by trimming. Five samples per site is the default. Response jitter is population standard deviation of per-round three-site averages.

The original-package small-sample speed method reads a bounded 512 KiB body through the selected candidate, requiring 95% completion, an 8-second I/O timeout, a 7-second body-time limit and the saved speed minimum. Named inbound listeners and routing evidence prevent concurrent selector races. The speed target is Google's download service because EdgeTunnel can locally intercept `speed.cloudflare.com`; a local 204 is not accepted as speed evidence. The site target defaults to `www.cloudflare.com/cdn-cgi/trace` independently of startup validation.

Proxy concurrency is bounded by the saved upper limit. Production probes use verified candidate-specific TLS connections, warm once per site, then measure five responses without rebuilding the connection each time. Google and GitHub use HEAD; Cloudflare trace uses GET, requiring HTTP 200 and an actual trace body. Timing ends at response headers, before body draining. This retains the warm-response timing principle of [Mihomo unified delay](https://github.com/MetaCubeX/mihomo/blob/v1.19.32/adapter/adapter.go). Closed/incompatible HEAD connections use the named core API, checking its per-URL `extra.alive` status evidence as well as delay. The upstream delay route can return a nonzero delay despite mismatching HTTP status; a delay number alone is insufficient. Trace fallback uses a verified GET, never an unsupported HEAD. Warmup is not a counted measurement. The original core User-Agent is retained. Adaptive mode starts at most 24 workers and reduces concurrency when widespread failures coincide with slow successful responses; invalid candidates alone do not force serial testing. Impossible loss limits finish early. Screening uses one valid geography provider; final competition confirms configured providers. Quotas plus a retest margin allow early competition without lowering quality limits.

## Direct TCP/TLS method

The original TCP probe connects directly to the candidate IP and port three consecutive times. Average latency and population-standard-deviation jitter use successful samples. Loss is failed attempts divided by all three attempts. A timeout remains a failure; each attempted connection is recorded. Optional TLS independently performs three verified handshakes with `www.cloudflare.com` SNI, measuring connection plus handshake time and enforcing saved latency/loss/jitter rules. Independent TLS is disabled in the initial preset, matching the supplied package's saved TCP selection. HTTPS download still validates TLS when that separate check is off.

Direct speed uses the original pinned-IP probe with `speed.cloudflare.com` SNI, the configured sample size and strict body completeness/timeout/speed limits. It never loads proxy authentication, changes the system proxy or creates an application proxy core. Existing operating-system routes still apply. Trace `colo` supplies an edge location from the bundled mapping; client `loc` is ignored. Unknown geography cannot qualify for the additional Japanese quota.

## Competition and output

Each method separately saves ordinary and Japanese publication counts. Its new shortlist and previous cloud results compete under fresh measurements, including all three TCP samples in direct mode. Failed retests replace stale passes. Saved-rule changes restart final competition. Rank proxy results by loss, successful observations, trimmed composite, jitter, speed, entry latency and stable address tie-breakers. Rank direct results by TCP loss, average, jitter, speed and stable address tie-breakers. Reserve the best eligible Japanese append candidates, select the ordinary quota, then append unique Japanese winners.

Automatic output requires all configured slots. Explicit manual output may contain fewer qualified addresses, with actual counts recorded in health metadata. Both local packing and Ubuntu decoding verify namespace, mode, quotas, uniqueness, ranks, text consistency and the full output set. Proxy files use `output/`; direct files use `output/Nodes-TCP/`. Neither method substitutes its measurements for the other.
