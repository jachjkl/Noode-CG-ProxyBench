# Benchmark methodology

Entry screening performs bounded local TCP connects with default concurrency 256 and a 1.2-second timeout. It is a preliminary reachability observation, not authenticated proxy traffic. Failed connections and entries above the saved entry-latency limit are excluded before loading proxies. The default entry limit is strictly 200 ms; a 240 ms entry cannot pass that rule. This observation is separate from website response timing.

Default proxy sites are Google gstatic generate_204 (204), Cloudflare cp.cloudflare.com (200-399), and GitHub (200-399). If Cloudflare preflight fails at cp but succeeds at the permitted trace endpoint, the whole run consistently uses trace (200) and records the selected URL.

The isolated core enables `unified-delay`, matching the owner's active Clash configuration. [Mihomo documents this timing mode](https://wiki.metacubex.one/en/config/general/#unified-delay) as removing handshake differences from measured RTT. The first connection still requires the candidate's real authentication and transport to work; the reported warm response does not include all connection-establishment time. A Clash single-site HTTP 204 result and this application's three-site mean are different observations and must not be compared as identical values.

Each round visits the three sites across the batch before the next round starts. Each site must have at least five observations, with five as the default. Sort that site's observations, discard exactly one minimum and one maximum, and average the remaining values. Five observations retain three; six retain four. The final composite is `(Google trimmed mean + Cloudflare trimmed mean + GitHub trimmed mean) / 3`. Defaults require zero failures and a composite no greater than 200 ms, with a 3-second request timeout and up to 60 concurrent site checks. Unified delay can issue a warming request before its timed request, so 15 observations need not correspond to exactly 15 underlying HTTP requests. All raw observations, discarded values, retained values, site means, and the final composite are recorded. Request success is evaluated over every observation: discarding a latency outlier does not discard its failed-request status. Failed observations use the configured timeout when relaxed loss rules permit them.

Network speed retains the original local package's algorithm: one HTTP/1.1 transfer of 524,288 bytes (512 KiB), at least 95% body completion, an 8-second I/O timeout, a 7-second body deadline, and a default minimum of 3 Mbps. Timing begins after HTTP headers. Speed is received bytes times eight, divided by body seconds and 1,000,000, rounded to three decimal places. The original 1 ms timing floor is preserved. Timeout, an incomplete body, and missing candidate route proof cannot qualify. This is a small-sample speed observation, with no additional startup bandwidth acceptance gate.

The default endpoint is `https://dl.google.com/chrome/install/standalonesetup64.exe`, using a bounded 512 KiB HTTP range. HTTP 200 or a matching HTTP 206 range is accepted. TLS certificate verification remains enabled. This avoids the special local-response treatment that some upstream EdgeTunnel paths apply to the former Cloudflare speed endpoint.

Each speed or geography request uses HTTP CONNECT through the selected candidate's dedicated loopback Mihomo listener and InName rule. At most four such checks run concurrently. Successful requests require a controller connection chain containing the exact candidate and excluding DIRECT. Production nodes never compete by changing one shared selector. The compatibility shared-listener fallback remains serial.

Ranking considers request loss, successful observations, the three-site trimmed composite, jitter, speed, entry latency, and stable IP/port tie breakers. The new ordinary TOP100 and previous ordinary TOP100 undergo fresh entry and proxy retests before selecting the final 100. New Japanese TOP10 and previous Japanese TOP10 compete for ten separate append positions. The Japanese quota uses the same saved rules and requires verified exit geography. Failed competition measurements revoke stale qualification. Published JSON retains explicit ranks and array order; text output uses the identical order.

Runtime initialization checks 1/10/100 node loading and isolated rule-mode routing. Cloudflare endpoint preflight is advisory and records a permitted fallback. Each candidate is qualified against its effective rules. The Chinese interface shows eight summary columns and 300 rows per page; its detail dialog retains site-by-round and speed observations.

Saved rules remain authoritative across closure and restart; values matching an older default are not silently replaced. The former three-observation count is upgraded to the explicitly required minimum of five. Resuming an older measurement policy archives its results and remeasures the saved candidate pool under the new method. Discovery-session exclusions remain unchanged, so the fixed feeds are not fetched again. Rules edited during an active batch apply to the next batch, and an edit before publication invalidates the older final competition and triggers a fresh retest.
